## Installing `trop`

With a Rust toolchain installed, you can install the published binary crate from crates.io:

```bash
cargo install trop-cli
```

The Cargo package is named `trop-cli`; the installed binary is `trop`. (If you happened to install the early `0.1.0` crate, see the [upgrade note](../reference/#release-and-upgrade-notes) to move to `0.2.0`.)

To build and install directly from a local checkout instead:

```bash wrap
git clone https://github.com/plx/trop.git
cd trop
cargo install --path trop-cli
```

## Reserving a single port

Run `trop reserve` from the directory you want the port associated with, and pass the result to whatever flag or environment variable your server expects:

```bash
PORT=$(trop reserve) &&
  npm run dev -- --port "$PORT"
```

It works the same way in a `justfile` or `Makefile`:

```makefile
port := `trop reserve`

dev:
    npm run dev -- --port {{port}}
```

A few useful options on `trop reserve`:

- **Preferred port (`--port 8080`):** On a _new_ reservation, `trop` tries port `8080` first before falling back to scanning your configured range. On an existing reservation, `trop` keeps returning the already-stored port unless you also pass `--overwrite`.
- **Pick a fresh port (`--overwrite`):** Re-runs allocation for the current key (preferring `--port` if supplied and free, or reusing/scanning within the range).
- **Explicit target directory (`--path /path/to/dir`):** Reserves against a specific path rather than the current working directory. By default `trop` only lets you target the current directory, an ancestor, or a descendant unless you pass `--allow-unrelated-path`.

## Multiple ports in one directory (`--tag`)

When a single worktree runs more than one local process—say a frontend dev server, an API server, and a local mock or database—give each one a tag:

```bash wrap
WEB_PORT=$(trop reserve --tag web)
API_PORT=$(trop reserve --tag api)
DB_PORT=$(trop reserve --tag db)
```

Each `(directory, tag)` pair gets its own steady port, and all of them stay tied to that directory so they clean up together when the worktree is removed. An untagged `trop reserve` call remains separate from every tagged reservation at the same path.

## Service groups

If you always reserve the same set of tagged ports in a repository, you can put them in a `trop.yaml` file at the project root instead of scripting multiple `trop reserve --tag` calls:

```yaml
reservations:
  services:
    web:
      offset: 0
      preferred: 8080
      env: WEB_PORT
    api:
      offset: 1
      env: API_PORT
    db:
      offset: 2
      env: DB_PORT
```

Here each service names an `env` variable, a unique `offset` within the group, and an optional `preferred` port. `trop` claims any available `preferred` ports first; for any service without a free preference, it finds the lowest base port in your range where all remaining offsets fit without colliding. The whole group is recorded in a single SQLite transaction—either every service gets a port or nothing changes.

From the project root or any subdirectory inside it, run:

```bash wrap
trop autoreserve --format human
```

`autoreserve` walks upward from your current directory until it finds `trop.yaml` or `trop.local.yaml`, and keys the reservations to the directory containing that file. (If you want to point at a specific file path directly, use `trop reserve-group ./trop.yaml`.) Repeating `autoreserve` reuses an existing compatible group; if you later edit `trop.yaml` to add or reshape services, pass `--force` to replace the directory's stored tagged group atomically.

### Choosing an output format

Group commands print their mapping to stdout without mutating your current shell environment directly:

- `--format human` — readable summary for terminal inspection
- `--format json` — structured service-to-port mapping
- `--format dotenv` — `KEY=PORT` lines suitable for writing a `.env.local` file
- `--format export --shell zsh` (or `bash`, `fish`, `powershell`) — shell export statements

To keep `dotenv` and `export` output safe to consume, every service's environment variable name must be a valid portable identifier matching `[A-Za-z_][A-Za-z0-9_]*` (and unique ignoring ASCII case). If you omit `env`, `trop` derives one from simple ASCII tags by uppercasing letters and turning `-` into `_`; other tag names require an explicit `env` field.

## Inspecting and cleaning up

Stopping a server leaves its reservation in `~/.trop/trop.db` so it is still waiting for you next time. When you actually want to inspect what is reserved or clear out old worktrees, use these commands:

| Command                                   | What it does                                                                                                      |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `trop list`                               | List active reservations as a table (`--format json`, `csv`, or `tsv` also work).                                 |
| `trop port-info 5000 --include-occupancy` | Show whether port `5000` is reserved in `trop` and whether anything is currently listening on it.                 |
| `trop release --tag web`                  | Drop just the `web` tag for the current directory.                                                                |
| `trop release`                            | Drop all tagged and untagged reservations at the current directory (add `--recursive` to include subdirectories). |
| `trop prune --dry-run`                    | Preview reservations whose directories have been deleted or turned into broken symlinks.                          |
| `trop expire --days 30 --dry-run`         | Preview reservations that haven't been touched in 30 days.                                                        |
| `trop autoclean --dry-run`                | Run both `prune` and `expire` together in one pass.                                                               |

Drop `--dry-run` when you're ready to delete the matching rows. If you move or rename a worktree and want to keep its existing port assignments rather than allocating new ones, `trop migrate --from <old> --to <new> --recursive` updates the stored paths in place.
